# Zone80 Worker CC-02 (Linux synthetic only)

Uses an exact hash-pinned copy of CC-01 helpers. Python 3.13.5 standard library, Linux flock and /proc. No actual GIS/native jobs, Windows support, scheduler, or game files. The scope and approval fields are descriptive, not authentication; run only in a trusted, new synthetic sandbox. Existing CC-01 state cannot be migrated to CC-02 automatically.

From this directory: `python -m unittest -v test_worker.py`. Test manifest helper: `python -c 'import json; from test_worker import manifest; print(json.dumps(manifest(),indent=2))' > demo.json`. Then `python worker.py init ./zone80-synthetic-demo`; `python worker.py run ./zone80-synthetic-demo --manifest demo.json` twice. `stop.request` inside the sandbox prevents new starts and cancels active child; verified completed outputs preserved. After checking interruption and removing a stop request if appropriate, explicit `--recover` permits a new attempt only after inherited lock release and matching CC-02 protocol. Never manually remove a live runner.lock. Old attempt files stay for inspection.

Only fixed synthetic child modes: ok, nonzero, missing, wrong, delay, descendant, leader_exit. No custom shell or executable. All descendants in test modes inherit the lock and remain in the owned session; fixed alarms bound orphan lifetime. Signals sent only to child session group while leader PID remains unreaped. Linux /proc RSS is sampled (sum of member RSS, can double count shared pages, not hard tree/private/commit bound); child RLIMIT_AS per process, host memory and free disk preflight (not cgroup-aware). Power-loss durability, adversarial filesystem isolation, arbitrary descendants, Windows Job Objects, detached survival and native integrations not established. Do not use with real map assets.
