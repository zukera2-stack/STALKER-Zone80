# CC-05P — guarded synthetic GRM job and review manifest

This companion extends CC05O, not the native GRM source. Linux .NET SDK 10.0.404, pinned GRM/BIS, CC05B bridge, reviewed offline packages. Exact v03/cache input snapshots in Library. Only the fixed 480m inline OSM fixture, three road states, and two synthetic elevation deltas are accepted. No actual geography, elevation creation, native full renderer, disk map output, P: access, WRP/PBO, scheduler or production approval.

```
export DOTNET_PROCESSOR_COUNT=2 NUGET_CERT_REVOCATION_MODE=offline DOTNET_CLI_TELEMETRY_OPTOUT=1 DOTNET_NOLOGO=1
dotnet restore Zone80.JobProbe.csproj -p:GrmRoot=<source> -p:BridgeSource=<cc05b> --source <offline-feed> -p:NuGetAudit=false
dotnet build Zone80.JobProbe.csproj -p:GrmRoot=<source> -p:BridgeSource=<cc05b> --no-restore -c Release --disable-build-servers -p:GeneratePackageOnBuild=false
python verify_job.py <dotnet> <actual-bin>/Zone80.JobProbe.dll <v03-editor-config> <modelinfo.json> job.abandoned.json
```

The native child accepts exactly three local arguments (config, cache, job file), validates strict schema, exact input hashes and fixed fixture XML, checks full 27-name catalog against explicit dispositions before generation. No command/path/layer fields allowed in job JSON. 12 active synthetic generators, SidewalksGenerator invoked only to assert zero, BuildingGenerator disabled for ZPB, 13 pending (not a permanent ban). No arbitrary layer activation. The synthetic child produces one RESULT_JSON line with all records, plus diagnostic stdout; the Python verifier validates count, IDs, content hashes, review digest and ownership before accepting a successful test. No records committed as production data. Logical IDs derive from fixture ID + layer and non-height placement key (not source IDs or durable real-world object identities); content digest includes elevation fields and world Z. Changed transforms or geometry may change IDs. Ambiguous key fails; no fabricated source lineage. Review/sector are included in separate review digest. Job ID normalizes field order and formatting and binds state, delta and exact config/cache/fixture hashes, but not executable hash, runtime fingerprint, expiry, approval or worker attempt ID. External worker contract must add those checks before integration. Validation is not a hostile-process security boundary or a signed manifest. The test verifier checks only the bounded format and invariants, not actual physical geometry or a full independent native computation.

Two complete identical suites, each 5 native jobs, 20 input refusals (19 invalid job documents + changed cache), 6 modified result refusals. No GUI, no worker/sector process integration, no durable manifest publication, general OSM ingestion, complete lineage, independent sector generation/halo or real map. Stage 001 PARTIAL. Proposed next CC-05Q: bounded worker integration with executable/dependency hashes, attempts, output validation, cancellation and resume. Real gates remain unchanged.
