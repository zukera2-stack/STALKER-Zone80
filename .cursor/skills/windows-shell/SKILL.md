# Windows Shell — универсальный инженерный скилл
Версия 1.0 · 2026-11-26

## 1. Назначение и границы
Работай как локальный инженер: обнаруживай реальные возможности среды, выбирай штатный интерфейс приложения, выполняй задачу, проверяй результат и сохраняй доказательства. Не путай Windows Shell (в широком смысле оболочка ОС) с PowerShell (командная оболочка и язык сценариев). Этот скилл предназначен для локального Windows-агента, а не облачного Linux-агента. Подключённый GitHub или MCP сам по себе не даёт доступа к рабочему столу владельца.

Перед работой прочитай AGENTS.md и специализированные скиллы проекта. Их более строгие ограничения имеют приоритет. Не устанавливай ПО, не меняй лицензии, системные политики, службы, ACL, антивирус или настройки безопасности без отдельного разрешения. Не запрашивай повышение привилегий по умолчанию.

## 2. Приоритет интерфейсов
1. Документированный CLI, пакетный режим, официальные API/SDK или встроенный язык сценариев.
2. PowerShell/Python для orchestration: файлы, запуск, проверка процесса, логи.
3. MCP и API уже открытого приложения, если подтверждены идентичность проекта и готовность.
4. Win32 и UI Automation (UIA): сначала наблюдение, затем разрешённые семантические операции через поддерживаемые patterns.
5. Ручная операция владельца, если штатный программный путь недоступен.

Не используй SendKeys, координатные клики, pyautogui, имитацию мыши или слепое посылание сообщений. Не подменяй отсутствие API неподтверждёнными внутренними командами. UIA Invoke/Value/Selection допустимы только при явном разрешении проекта и проверке целевого элемента. Не внедряй DLL или код в чужой процесс.

## 3. Начальный аудит (read-only)
Запусти `scripts/Probe-Windows.ps1` или эквивалентный точечный набор команд. Зафиксируй:
- ОС, PowerShell edition/version, архитектуру процесса, текущий каталог, интерактивность и session ID;
- доступность git, dotnet, python, py, pwsh, конкретного exe, его версию и фактический путь;
- PID, SessionId, путь и время запуска целевого процесса, наличие окна;
- Git root, ветку, полный HEAD, git status; состояние удалённой ветки отдельно;
- наличие разрешённого проекта и дисков, свободное пространство, зависимости.

```powershell
$PSVersionTable
[Environment]::Is64BitProcess
[Environment]::UserInteractive
(Get-Process -Id $PID).SessionId
Get-Command git,dotnet,python,py,pwsh -ErrorAction SilentlyContinue
Get-Process -Name Unity -ErrorAction SilentlyContinue |
    Select-Object Id,SessionId,Path,StartTime,MainWindowHandle
```

`Get-Command` не нашёл exe ≠ программа не установлена. Используй известный путь, записи установки или документацию приложения; не сканируй весь диск без необходимости. CIM/WMI и свойства чужих процессов могут быть недоступны: UNKNOWN, а не нулевые значения. Не выгружай все переменные окружения, токены, реестр или сведения об аккаунте.

## 4. Правила PowerShell
Поддерживай Windows PowerShell 5.1 и PowerShell 7 там, где это возможно. Не используй синтаксис PS7 в 5.1 (`??`, `&&`, `ForEach-Object -Parallel`). Определи оболочку до запуска. Используй `-LiteralPath` для пользовательских путей, `Join-Path`, абсолютные пути и массивы аргументов; не склеивай произвольный код и не вызывай `Invoke-Expression`.

```powershell
$ErrorActionPreference = 'Stop'
$root = (Resolve-Path -LiteralPath $ProjectPath).ProviderPath
Push-Location -LiteralPath $root
try {
    & git status --short --branch
    $code = $LASTEXITCODE
    if ($code -ne 0) { throw "git status exit=$code" }
} finally { Pop-Location }
```

Для нативных exe проверяй `$LASTEXITCODE` сразу; `$ErrorActionPreference` сам по себе не гарантирует обработку ненулевого exit code. Для PowerShell-команд используй `-ErrorAction Stop` там, где нужен terminating error. Не скрывай исключения пустым catch. Для JSON указывай глубину ConvertTo-Json; для машинных артефактов задавай кодировку явно (UTF-8 без BOM через .NET при необходимости одинакового результата 5.1/7).

## 5. Файлы и Git
Перед изменением установи точный корень и SHA, перечитай `git status --porcelain=v1`. Не перезаписывай пользовательские файлы. Для целевых файлов сохрани резервную копию вне репозитория, SHA-256 и diff. Проверяй, что путь не выходит из разрешённого корня, в том числе через junction/reparse point; при сомнении остановись. Не меняй системные/игровые ресурсы и защищённые диски (например P:) без разрешения.

```powershell
& git rev-parse --show-toplevel
& git rev-parse HEAD
& git branch --show-current
& git status --porcelain=v1
& git diff --stat
Get-FileHash -LiteralPath $File -Algorithm SHA256
```

Не применяй `reset --hard`, `clean`, force checkout/push, автоматический stash/drop, массовое удаление или перезапись. Не сливай PR, не удаляй ветки и не меняй main без разрешения. Стадируй только явно перечисленные файлы; проверь staged diff. Не публикуй бинарники, приватные ресурсы, локальные настройки или сырые логи с персональными данными. Если checkout конфликтует с незакоммиченными изменениями — BLOCKED, а не обход через новый проект.

## 6. Запуск и контроль процессов
Сначала установи, работает ли приложение владельца. Не закрывай и не перезапускай его без разрешения; используй только подтверждённый экземпляр. Для запуска принадлежащего агенту процесса веди PID, время старта, executable, working directory, аргументы (без секретов), stdout/stderr, timeout и exit code. `Start-Process -ArgumentList` склеивает элементы в строку; при путях с пробелами требуется корректное quoting. Для PS7 можно использовать .NET ProcessStartInfo.ArgumentList; для 5.1 тщательно проверяй сформированную командную строку либо используй `& $exe @args` с простыми аргументами.

```powershell
$p = Start-Process -FilePath $exe -ArgumentList $verifiedArgumentString `
    -WorkingDirectory $root -PassThru -RedirectStandardOutput $stdout `
    -RedirectStandardError $stderr
if (-not $p.WaitForExit(120000)) {
    # Не убивать автоматически: зафиксировать PID и TIMEOUT, проверить владение.
    throw "TIMEOUT pid=$($p.Id)"
}
$p.WaitForExit()
$exitCode = $p.ExitCode
```

Timeout не означает, что процесс завершён. Не запускай дубликат поверх ещё работающего задания. Остановку разрешённого собственного процесса проводи после проверки PID/времени запуска/пути, сначала штатным методом; не используй массовый Stop-Process по имени. Если приложение требует interactive desktop, проверяй session и window station. Наличие GPU или процесса не доказывает, что приложение готово. Отдельно проверяй окно, состояние загрузки, лог и фактический результат.

## 7. Win32 / UIA
Для GUI-программ без достаточного CLI начни с read-only инвентаризации окон и UIA дерева. `Get-Process.MainWindowHandle` может быть 0 даже при наличии окон. При необходимости используй документированные EnumWindows, GetWindowThreadProcessId, GetWindowText и IsWindowVisible; сверяй PID и SessionId. Проверяй архитектуру x86/x64 для P/Invoke и нативных DLL. Не считай окно с заголовком приложения доказательством корректной загрузки проекта.

UIA: AutomationElement.FromHandle, FindAll, Current.Name/AutomationId/ControlType, IsEnabled и GetSupportedPatterns. Не полагайся на локализованный заголовок как единственный идентификатор. Не считай наличие pattern доказательством корректного выполнения команды: после Invoke/SetValue проверяй состояние. Не обходи UIPI, UAC, защищённый рабочий стол или чужую сессию. Для ошибок графики отдельно различай запуск процесса, создание окна и успешную инициализацию графического устройства.

## 8. MCP: проверка и восстановление
MCP — специализированный канал приложения, не замена shell. Перед изменяющими командами проверь фактический список доступных инструментов, endpoint, идентификатор экземпляра, root проекта, версию приложения, состояние готовности и свежесть heartbeat. Для локального порта можно выполнить `Get-NetTCPConnection -LocalPort $port` и `Test-NetConnection -ComputerName 127.0.0.1 -Port $port`; порт должен быть взят из реальной конфигурации. HTTP 200 или открытый порт не доказывает готовность редактора. Не выдумывай MCP endpoints и имена инструментов.

Если `WebSocket is not initialised` / `stale_status`:
1. Зафиксируй предупреждение, stack trace, версию пакета, время heartbeat, PID и фактический проект.
2. Проверь, не идёт ли компиляция, domain reload, PlayMode transition или диалог. HTTP и WebSocket диагностируй отдельно.
3. Если разрешено, переподключи штатным способом клиент/сервер MCP, не переустанавливая пакет и не закрывая редактор владельца.
4. Повтори read-only запрос: правильный root, свежий state, `ready_for_tools=true` (если такой контракт есть). После reload повтори проверку.
5. При сохранении ошибки: BLOCKED_MCP, переходи на CLI только если он безопасен для открытого проекта. Не отправляй изменяющие команды в неизвестный экземпляр.

Причину гонки/разрыва подтверждай по журналу и исходникам установленной версии; не объявляй гипотезу доказанной. Не открывай сетевые порты наружу и не отключай firewall ради соединения.

## 9. Профили приложений
- Unity: один согласованный Unity Hub проект, ветки переключаются внутри него. Не создавать дополнительные clone/worktree для обхода ошибок. Перед переключением сохранить сцены и локальные ProjectSettings/URP с согласия владельца; не терять GUID/.meta. Не запускать второй batch Editor на уже открытом проекте. Использовать MCP, Editor API или отдельный согласованный запуск CLI после штатного освобождения проекта. Сверять версию Editor и backend. Для тестов сохранять XML/JSON, количество реально выполненных тестов, Console, BuildReport, Player.log и exit code. Ноль зарегистрированных тестов — NOT_RUN. Mono и IL2CPP — разные gates. Видимое окно не доказывает визуальную приёмку.
- Blender: документированный background CLI и Python API bpy, проверка exit code, повторное открытие результата, параметры mesh/rig/animation и экспорт. Не заменять визуальный тест только наличием файла.
- Global Mapper: закрепить версию/лицензию; сначала GMS batch, затем официальный Python API/SDK при наличии. Не считать отсутствие инструмента в PATH доказательством его отсутствия. Не смешивать Desktop Pro и отдельно лицензируемый SDK. Не использовать сеть, если задача требует offline.
- Arma 3 Tools: проверять реальные exe, диск P:, сессию, архитектуру, Buldozer/RPT. Не модифицировать P: и оригинальные ресурсы без разрешения. Для Terrain Builder использовать документированные CLI/API и разрешённые UIA patterns, не имитировать ввод. Не считать D3D smoke подтверждением импорта карты или сборки WRP/PBO.
- Git/.NET/Python: фиксировать версии, точные зависимости, исходный SHA, exit code и результаты тестов. SDK/runtime/targeting pack — разные вещи. Не устанавливать зависимости глобально, если достаточно локальной среды.

## 10. Воспроизводимость и доказательства
До запуска сформулируй критерий успеха и отрицательный сценарий. После запуска проверь не только exit code, но ожидаемые файлы, их размер/hash, число тестов, семантический результат. Успех на старом SHA не наследуется автоматически. Не повторяй уже подтверждённый платформенно независимый тест без причины; сначала используй доступную Linux-среду, затем остаточные Windows-тесты.

Храни локальный отчёт вне репозитория либо в согласованном ignored reports-каталоге. Публикуй очищенные доказательства и SHA-256. Не публикуй секреты, имена аккаунтов, машинные идентификаторы и приватные пути без необходимости. Статусы: PASS (исполнено и проверено), FAIL (исполнено, критерий нарушен), BLOCKED (препятствие), NOT_RUN, PARTIAL, TIMEOUT. При отсутствующих журналах CI не делать вывод о компиляции.

Минимальный отчёт: задача; время UTC; SHA/dirty state; среда; команды и версии; результаты/exit codes; артефакты и hash; изменения; восстановление настроек; блокеры; следующий шаг. Разделяй наблюдение, гипотезу и подтверждённый результат.

## 11. Рабочий цикл
Discover → Validate target → Plan → Execute → Verify → Restore → Report.
При ошибке локализуй слой (среда, лицензия, transport, API, данные, приложение), воспроизведи минимальный случай, исправь только разрешённое, повтори тест. Не продолжай изменять мир после частично выполненной команды, если нет доказанной идемпотентности. Не обещай работу в фоне без реально запущенного механизма.

## 12. Комплект
`scripts/Probe-Windows.ps1` — read-only аудит, сохраняющий JSON по явному пути; `references/REPORT_TEMPLATE.md` — форма отчёта. Сценарий не запускает/закрывает приложения, не меняет Git, не устанавливает ПО. Синтаксис рассчитан на PS5.1/7; Windows runtime-проверка этого нового файла ещё требуется.
