## План GRM-01

Проверен локальный чистый upstream v0.11.1, commit `2aef2040836daa11a8a368bb0c7f9ecd8f405d65`. HEAD и разыменованный тег совпали.

- `grma3 gentb` через `Program.GenerateTerrainBuilder` вызывает `GenerateTerrainBuilderFiles`. Генератор загружает OSM через `OsmDataOverPassLoader`, создаёт контекст, пишет конфигурацию, дороги, изображения, высоты и объекты, затем вызывает `ProcessImageToPaa`. У CLI есть целевой каталог, но этой команды недостаточно для гарантированного офлайн-прогона. Команда `layer` выбирает один генератор объектов и тоже зовёт загрузчик OSM. [CLI](https://github.com/jetelain/ArmaRealMap/tree/2aef2040836daa11a8a368bb0c7f9ecd8f405d65/GameRealisticMap.Arma3.CommandLine) · [Генератор](https://github.com/jetelain/ArmaRealMap/blob/2aef2040836daa11a8a368bb0c7f9ecd8f405d65/GameRealisticMap.Arma3/Arma3TerrainBuilderGenerator.cs)
- Объекты разделены на `absolute_*.txt` и `relative_*.txt`. Строка содержит имя модели, X со сдвигом 200000, Y, углы, масштаб и высоту. Идентификатор источника следует хранить в сопроводительной таблице до генерации строки. Сопоставление имени модели с canonical model path следует проверить по библиотекам TML. [TerrainBuilderObject](https://github.com/jetelain/ArmaRealMap/blob/2aef2040836daa11a8a368bb0c7f9ecd8f405d65/GameRealisticMap.Arma3/TerrainBuilder/TerrainBuilderObject.cs)
- `elevation.asc` экспортируется с TB Easting 200000 и NoData −9999. Для `satmap/idmap` используются те же TB-якоря с поправкой на позицию части. Экспорт изображений требует `IdMapMultiplier == 1`. Проверить ось Y, привязку пиксель/угол и физический размер каждой части по заголовкам и контрольным меткам. [Экспорт рельефа и изображений](https://github.com/jetelain/ArmaRealMap/blob/2aef2040836daa11a8a368bb0c7f9ecd8f405d65/GameRealisticMap.Arma3/Arma3TerrainBuilderGenerator.cs#L174-L236)

1. Для отдельного разрешённого эксперимента подготовить два соседних синтетических сектора, общую сетку высот с NoData, детерминированные маску и спутниковую заглушку, контрольные точки и локальный источник OSM. Подать источники в тестовый BuildContext через локальный адаптер. Заблокировать сеть и вызовы упаковки/конвертации. Писать только в отдельные каталоги W/E.
2. Сравнить как минимум два ориентира в секторе по каждой оси и один объект на шве. Проверить гипотезу `globalX = sectorOffsetX + tbX - 200000`, `globalY = sectorOffsetY + tbY`. Для W смещение (0, 0), для E (256, 0) в этой фикстуре. При обратной сериализации прибавить TB XShift ровно один раз. Отдельно согласовать высотный режим с потребителем.
3. Для каждого объекта сопоставить source_id, owner, model path и height mode. Обрезанные линии и полигоны сверить по частям на шве. Прогнать полузамкнутые границы и включённый внешний край, отфильтровать дубли буфера. Сверить NoData и перепроецирование в конечном потребителе, затем повторить только W и сравнить размеры, SHA-256 и профиль памяти.
4. Допуск ограничен синтетикой. Реальный сектор, утверждение CRS, WRP и PBO требуют отдельного решения владельца.

Полная карта, GRM, WRP и PBO в рамках GIS-04 не запускались. Данные не загружались из сети. Результаты не меняют Stage 001.
