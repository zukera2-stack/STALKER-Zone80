2. План в существующем Issue/документе этапа: файлы и контракты, критерии, отрицательные случаи, воспроизводимые команды. Укрупнить задания Cursor, не дробить на микрозадачи.
3. RED-GREEN-REFACTOR: сначала тест или контрольный измеримый сценарий, выполнить на исходнике и подтвердить ожидаемую причину FAIL; затем минимальное изменение, GREEN, рефакторинг и регрессия. Для геоданных — CRS, преобразование координат, исходные хеши, границы растра, размерности, детерминированность, согласованность импорта/экспорта и результат readback; точные допуски брать из действующего контракта. Не подменять отсутствие нативного readback офлайн геометрией. При блокировке RED_NOT_RUN с точной причиной; source-only ≠ PASS. Для документов — статический baseline/after, не runtime TDD.
4. Debugging: команда/exit, воспроизведение, граница сбоя (GIS/GRM/worker/импорт/Terrain Builder/Buldozer), факты, проверяемая причина, узкое исправление и повтор того же сценария. Не подгонять тест к ошибке. UI Automation: сначала read-only состояние и штатные пути, соблюдать no-focus guards, никаких неподтверждённых Invoke или обхода foreground.
5. ChatGPT выполняет доступный анализ, скрипты, офлайн QA и независимую приёмку; Cursor — конкретное нативное исполнение через локальные PowerShell/штатные инструменты и реально блокированные локально проверки. Субагенты только при наличии реального инструмента и независимых задач; иначе inline и отдельный собственный review, не фиктивная независимость. Отдельная ветка и собственная песочница. Не переключать чужой checkout, не менять общие ресурсы P:, штатный read-only buldozer.cfg, чужие процессы или проектные данные без допуска. Не создавать конкурирующие инструменты.
6. Review: проверить diff, provenance, исходные хеши, фактические данные и логи, риски, результаты на точном tested SHA. Проверить замечания до исправления. Исторический PASS не равен новому PASS; офлайн пакет не доказывает Save/Reopen, Mapframe или Buldozer. Нативные прогоны только по действующим воротам. Для docs-only сверить изменённые пути и сохранение исходного текста; runtime не повторять без причины.
7. GitHub — код/Issue/статус; Google Drive — INPUT/OUTPUT/QA/ARCHIVE, локальный mount определить, manifest/уникальный ZIP/размер/SHA256/назначение/путь в Issue, независимая проверка получателем. Desktop Commander не использовать. Без публичного доступа, overwrite, merge, удаления веток/результатов, автоматического cleanup, изменений main. При блокере сохранить локально, указать причину, продолжить независимое.
