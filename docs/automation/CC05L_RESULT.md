## Dependencies and scope
Original LakesBuilder uses road/rail embankment priority and clips lakes to a 25m inset of the area. WatercoursesBuilder consumes LakesData and RoadsData, not elevation, and subtracts lakes from paths and ordinary road clear polygons from surface geometry. SandSurfacesBuilder has empty priority; native OceanData/CoastlineData tested only on land-only input (no actual coastline). WatercourseGenerator consumes ConditionEvaluator and WatercoursesData; uses native cluster and additional collections. Only final synthetic ElevationData explicitly preseeded. Actual WatercourseRadialData request refused at ElevationWithLakesData; no fake lake elevation cache. Source review: full IdMapRenderBase reads ElevationWithLakesData directly; therefore full IdMapRender NOT RUN. AsphaltBuilder reads ForestData and AerowaysData; complete landcover/material priority graph not yet tested. No satellite acquisition.

## Defects and review
Watercourse.IsTunnel uses TypeId >= RiverTunnel but StreamTunnel enum precedes RiverTunnel; measured StreamTunnel.IsTunnel false. Initial test correctly fails expected tunnel boolean; final test records measured defect, does not certify correct tunnel handling. Width fixed at 10m for rivers and 4m for streams in source; width tag ignored in fixture. Waterway=canal unsupported by targeted path parser in fixture. LakesBuilder edge inset demonstrably removes part of pond; rationale in upstream source is historical pond-model exporter failures, not verified necessity for Zone80 geometry-only pipeline. Preserve source geometry/IDs; do not silently accept omission or flatten GM heights. Broad river/reservoir polygon and relation support, actual shore continuity, water elevation/plane, narrow stream/canal/ditch policies, protected road crossings and physical fit remain untested. Ice/mud/base and asset rights unresolved.
