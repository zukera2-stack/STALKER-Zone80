## Measured implementation
Read-only parser for the fixed MAP-003 64×64/30 m pilot at E294373.084/N5698122.108, EPSG:32636, EGM2008 as documented in the owner report. Strict corner ASC header, row count/length, finite bounded numeric tokens, NoData=-9999, exact SHA and declared metadata, north-first row orientation and exact existing cell-center queries via Decimal. No interpolation, repair, output raster, or network. Actual mode accepts ONLY the pinned historical diagnostic archive/ASC/PRJ, not arbitrary future GM inputs or self-attested provenance. Exact PRJ hash pin is not a general CRS parser. Future exports require separate reviewed provenance/metadata and semantic CRS checks; no native consumer is authorized even with a full synthetic grid.

## Source findings and provider design (not C# implementation)
Pinned jetelain/ArmaRealMap v0.11.1, SHA 2aef2040836daa11a8a368bb0c7f9ecd8f405d65. Paths below relative to upstream.
- GameRealisticMap/BuildContext.cs (blob 60e060d36c28adabfecadab3f906bce6c5dbdc9e): GetDataTask caches typed tasks under semaphore; public SetData<T> sets completed task directly, outside semaphore. Candidate seam: before any consumers/concurrency, in a separate reviewed context factory. Do NOT call concurrently or merely overwrite after a builder has started.
- GameRealisticMap/BuildersCatalog.cs (0b6b855c8bbc03fc5fdae9250f68a5bd0a02d895): registers RawElevationBuilder and downstream builders; Register uses dictionary Add, not replacement. A reviewed allowlisted catalog/context guard is needed so an unprovided forbidden elevation type fails rather than invoking default fallback. No patch to installed binaries.
- GameRealisticMap/ElevationModel/RawElevationBuilder.cs (b731328ed9fbafaac83a28d6f90894878692521c): samples terrain nodes at x*cell,y*cell from external DEM with ocean mask; also computes out-of-bounds summaries (512 rays). No direct use allowed. RawElevationData (0f5329f0fd1343b25684dacf5718996481bfac10) can wrap a grid but its simple constructor supplies empty credits/out-of-bounds; not a substitute for real evidence.
- ElevationGrid.cs (6febce10ae9be0f247e7d1c61c12eb5a8f40b54f) indexes [x,y] over backing [y,x]; ToTerrain multiplies by cell size, native samples at 0,30,...,1890; interpolates triangularly and clamps boundaries. Current ASC centers at 15,45,...,1905. Copying cells without measured conversion creates 15 m shift per axis. Reversing ASC row order is necessary but insufficient. Do not silently translate map origin or use edge clamping, interpolation, or invented halo to compensate. TerrainAreaUTM.cs (65e5d14cb62d06aa1871628ace74e76899610899) uses UTM SW and geographic transforms; exact native CoordinateSharp corner roundtrip still untested.
- ElevationWithLakesBuilder.cs (e5290a22f55a725e8f3cf8e83eb33068047b95ab) mutates RawElevation grid with lake digging, embankments, aeroway and building flattening. ElevationBuilder.cs (16a41f0e1f7745dcb0f4cc2df442e3ac2ea4d98a) applies further road/rail/watercourse constraints. Injecting only RawElevationData would not preserve authoritative GM heights. ElevationOutOfBoundsBuilder.cs (adeed5b91a1221526dba9b97560d9cab4a94bac6) requests RawElevationData.OutOfBounds; no fake summaries.
- ConditionEvaluator.cs (c8a30689f694dc79dd5fe98c4db8f188f7393a5f) requires ElevationData unconditionally, plus CategoryAreaData, CitiesData, OceanData, RoadsData. ForestGenerator via ClusteredGeneratorBase/GeneratorBase.cs (07eaf69991197b2f32d771c1f117943847579302), and TreesGenerator directly, request ConditionEvaluator. ForestBuilder also requests CutlinesData and base priorities. TreesBuilder uses roads/buildings. These are partial source dependency paths, not full transitive proof. ElevationWithLakesData carries a lake list as well as grid; no fabricated empty lists.
- Arma3TerrainBuilderGenerator.cs (de37bf421ac18cf865089078565664f71c01a74f): GenerateOnlyOneLayer calls LoadOsmData (Overpass loader) then private CreateBuildContext using default BuildersCatalog; no offline/GM-only guarantee. ExportElevation uses ToDataCell with TerrainBuilderObject.XShift; native serializer alignment remains separately untested.

Proposed integration order: (1) GM26.2 complete source and documented target lattice/sampling convention for native grid, with 0 NoData and verified control positions; preserve original ASC. Obtain any separately needed node-compatible export through GM only, or review an explicit consumer coordinate mapping; no arbitrary resampling or modification of elevations. (2) prove exact native TerrainArea/coordinate convention, units/datum and edge/halo handling with asymmetric synthetic tests. (3) separate C# context factory and typed provider, inject approved grid before concurrent GetData; prevent default RawElevationBuilder, modifying builders and unapproved out-of-bounds/satellite/network paths from execution. Only supply typed lake metadata if genuinely verified. All unknown requests fail closed. (4) pinned offline OSM input and complete layer-specific transitive dependency audit, native parser/asset closure, hashes before/after to detect mutation; instrument forbidden builder calls. (5) owner-approved bounded local native test only after gates. No gentb/genwrp/genmod, no P: writes, no native GRM run in CC-05.
