## Bounded implementation
Actual 480x480m synthetic area, 16x16 node grid 30m, 9N/33E, independent dummy grid origin. Explicit fixture with 15 OSM ways (IDs 101–115), checked exact set. Native category, road, rail, building, lake, watercourse, sand, ocean/coastline, cutline, asphalt and airport/aeroway preparation used. Native GrassData and ForestData requests actually refused at ElevationWithLakesData; no fake height cache. Forest and seven other landcover classes selected by explicit fixture IDs and native geometry subtraction, not generalized OSM classification. Fixture has two categories, one road, one lake, one sand, no buildings/rail/cutlines/coast/aeroways; no actual ice feature. Therefore only the finite fixture graph is reviewed. ForestData explicitly injected to native AsphaltBuilder. Separate geometry-input SurfacePlan accepts every required slot as synthetic geometry or known absent in fixture; rejects missing/unknown/empty geometry/unexpected extra slot. No serialization or independently verified real-source absence. Mutable in-memory lists are review-only, not production contract.

Native public PolygonDrawHelper and native GetIdMapSize/TerrainToIdMapPixel used, with antialias off. Ordered draw plan based on observed precedence; own deterministic 64x64 crown stipple with RGB seed, not byte-equivalence claim to internal renderer. Separate semantic slot mask disambiguates shared material IDs. No production map output or native full IdMap. Candidate rule preserves asphalt geometry under vegetation without changing forest geometry, in contrast to actual stock AsphaltBuilder which subtracts forest. This is a bounded design experiment, not universal asphalt policy or simulated cracks.
