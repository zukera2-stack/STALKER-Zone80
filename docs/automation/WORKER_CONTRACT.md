# Zone80 Worker — local background execution contract v0.1 (proposal)
24.11.2026, Issue #42. This describes software Luna is to implement; not an installed worker, not authorization for unattended real map generation. Source baseline PR #47. Preserve GM-only elevation authority and current Stage 001 PARTIAL. Prefer existing local project runtime if suitable; otherwise a small Python stdlib or PowerShell/.NET runner, select based on measured Windows environment. No daemon or new framework required.
## Boundary
GitHub holds reviewed code/config templates; local queue is explicitly selected by owner/agent within current Issue scope, pinned to reviewed commit. No arbitrary remote code execution, polling Issue comments as commands, unattended git pull, passwords, upload of source data or raw machine logs. Local worker stops at queue end. Agent can exit; worker is a separate OS process. Keep output/cache/logs in designated existing ignored reports/ or output/ outside P:, choose real writable root after preflight. No writes to owner projects, P:, Windows configuration, installed tools or profiles. Only local owner-approved sandbox. Path containment is not OS isolation: for untrusted or nonredirectable app side effects use a proven isolated environment or BLOCKED.
## Job schema and state
Example configs/automation/map003-queue.json.example is intentionally disabled. Each job records stable ID, kind, predecessor IDs, exact scope, artifact input/output paths relative to root, source and executable hashes, limits, approval reference and expected validation. Manifest has schema version, reviewed code SHA, local approval and finite expiry. A job identity digest includes normalized manifest fields and content hashes; changed inputs invalidate cached PASS and dependent outputs. Actual paths, executable and resource ceilings local only. All kinds allowlisted in code, commands constructed from typed fields not arbitrary argv/shell. Allowed initial kind: synthetic_probe. Future reviewed adapters gm26_export and grm_layer require native and data authorization, real dependency gates. TB import manual/interactive separate, no unattended adapter now.
States: QUEUED -> PREFLIGHT -> RUNNING -> VALIDATING -> PASS; otherwise BLOCKED, FAIL, INTERRUPTED or CANCELLED. NOT RUN for unexecuted. Every state transition with UTC timestamp/reason. Exclusive single runner lock with OS-level ownership (not PID-only file); reconcile stale state by checking process identity/start time. If old child may be alive, do not rerun. Unique attempt output directories, never overwrite originals or failed evidence. Write state via temp + atomic replace; PASS only after exit 0 AND expected outputs validated, finite extents, hashes and durable manifest. Resume verifies digests; skip only valid PASS; never promote partial output. Block dependent jobs when prerequisite not PASS. On stop/crash recover INTERRUPTED, no silent success. 
## Resources and process isolation
One job at a time by default; suggested below-normal priority, measure actual host. Local limits explicit per job (max wall seconds, private/commit and working set bytes across owned tree, minimum system available RAM and free disk bytes). Proposed pilot defaults only after measuring capacity; reserve at least 4 GiB and 25% installed RAM if feasible, reserve 20 GiB disk plus estimated output, max one job and 30 min wall-time for first real candidate. Synthetic job max 30s. If limits cannot be measured, BLOCKED. No fixed RAM diagnosis from old logs. Use Windows Job Object or verified process-tree management, never Stop-Process by name or attach to owner instances. Avoid pipe deadlock, stream stdout/stderr separately. Stop request prevents new starts, attempts supported graceful cancel then bounded termination of verified owned tree only. Pause between jobs; do not suspend arbitrary GIS processes. No auto retry native until known transient classification, at most one for approved idempotent network failure with new attempt dir, backoff, no retries for invalid outputs, timeout/resource breach, policy errors, unknown exceptions. No hidden changes to sleep/power settings.

GM26.2 GMS: installed version/licence, precise existing script syntax, approved full N51E030, 64x64/30m with known origin, CRS/units/datum, 4096 finite real heights, NoData=0, 5 sample cells, logs and SHA; no other height generator. Retain old diagnostic evidence. GRM v0.11.1: validate actual binary/config/assets and dependencies before generation; no elevation, satellite/PAA, unapproved P: side effects. If layer needs elevation STOP; do not work around by deleting guard. No generic gentb/genwrp/genmod, no game, no automatic Terrain Builder import. Source online acquisition requires explicit bounded source/size/licence permission; no broad downloads. Source metadata stays local, redacted aggregate reports Git.
## Background mode and lifecycle
Phase A: interactive invocation, finite queue of synthetic probes, child process continues after terminal/agent closes only if actually tested. Phase B: independent noninteractive CLI job on existing user account and approved sandbox, prove process survives Cursor closure and locked desktop. Prefer manually started detached process with PID/log/status and stop controls. Phase C (only explicit owner approval after A/B): Windows Task Scheduler task under existing user with least privilege, one instance (IgnoreNew), finite execution time and bounded restart. First use logged-on user token; no password stored by worker, no SYSTEM/service or admin elevation, no autologon or power policy modifications. S4U lacks network/encrypted-file access; do not assume availability of P: or user-session tools. Verify permissions, drive visibility, real locked-screen behavior and license in exact session. No guarantee under sleep, hibernate, shutdown or logout. Optional resume at next logon only after owner approves task creation. Provide task status/disable/delete instructions for owner; never remove unrelated tasks. No scheduler registration in this assignment.

## Acceptance tests (synthetic first)
Positive: finite successful child writes expected artifact; stdout/stderr preserved, output/hash validation; sequential dependency and repeat resume skips proven result. Negative: nonzero exit, exit 0 missing/wrong output, stale hash, unknown kind, expired authorization, forbidden path/reparse escape, resource low, timeout, stop during job, crash during checkpoint, stale lock/live second runner, child spawns owned descendant, output path existing, no duplicate starts. Verify unrelated test sentinel process remains untouched, no writes outside sandbox. Simulate resource probe deterministically, then real measured process. Run twice with identical inputs; deterministic outputs excluding timestamps/logs. Test abrupt runner stop and restart without orphan duplication. Evidence: exact commands/exit codes, tool versions, UTC, test counts, input/output hashes, lock/ownership, peak memory/time, observed files. Background survival, locked desktop, scheduler, native GIS and TB report separately NOT RUN until tested. Stop after Foundation pilot; no automatic stage advancement.
