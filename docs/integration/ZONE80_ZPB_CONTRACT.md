# ZONE80–ZPB asset integration contract v1.0 (proposed)
Date 2026-11-24. Owner requested coordinated map/buildings projects. Shared design document, not acceptance of any model, placement, build or next stage. Map issue #42 and buildings issue #1 remain active. The identical contract is stored in both repos at docs/integration/ZONE80_ZPB_CONTRACT.md. If versions or content differ STOP and reconcile, no silent fork.
## Authority and boundaries
STALKER-Zone80 owns geographic source snapshots, stable building_id/source_id, WGS84 footprints, addresses, projected positions, terrain, sector ownership, instance matching and map-side GRM/TB adapters. STALKER-Pripyat-Buildings owns original model masters, model_id, dimensions, local footprint/anchor, facade vector, P3D path, classnames, package dependencies, materials, LOD, variants and model QA. Addon never depends on map. No direct private repo access from public CI; exchange reviewed metadata via local owner-approved versioned manifest, not models/geodata in public Git. No external license implied by private repository. Source facts, proxy models, gameplay modifications separate. Historical epoch not approved.
## Proposed naming contract
P-drive-relative resource prefix z\stalker_pripyat_buildings\addons\<package>. Model path in catalog begins with backslash; normalized case-insensitive comparison for collision detection, exact lower-case file/prefix path for portability. CfgVehicles and CfgPatches names as declared; no guessing base classes or requiredAddons. PBO file name is not requiredAddons class. Package buildings_60 -> zpb_buildings_60.pbo -> ZPB_Buildings_60 (reserved). Candidate packages buildings_84, buildings_96, buildings_121, buildings_highrise, landmarks, shared, core. Only declare real packages that pass QA. First reservation: model_id zpb.house.111_60_12.v01, family_id series_60, classname ZPB_House_111_60_12_V01, path \z\stalker_pripyat_buildings\addons\buildings_60\models\house_111_60_12_v01.p3d. No file or class exists yet; CANDIDATE. Do not silently reuse ID/class/path for incompatible footprint/pivot. Compatible fixes use version/hash; incompatible variants new ID/path/class. No placeholder PBO.
## Model catalog transfer
Producer: buildings project. Proposed catalog/assets.manifest.json (local release artifact). JSON UTF-8, schema_version=1, addon_release string, source_commit full SHA, assets array. Each asset: model_id, family_id, series (nullable), variant, epoch (nullable), status (CANDIDATE/MODEL_READY/RETIRED), package, pbo_filename, cfgpatches, classname (null if not class-based), p3d_path, model_sha256, dependencies (CfgPatches names), dimensions_m {length,width,height}, local_footprint_xy_m (closed polygon rings or null), anchor_xyz_m, facade_forward_xy (unit vector), ground_offset_m, allowed_scale (default 1), qa {source_review,model_roundtrip,build,engine,tb_template}, rights_status, evidence_refs. Null means unknown, not zero. Candidate must not be selected for placement. MODEL_READY requires measured footprint/dimensions/anchor/forward, real file/hash/config/PBO prefix, approved rights and evidence of roundtrip/build/engine/template checks; if TB gate unavailable remains candidate. Manifest records only owned/approved resources. Hash manifest bytes and pin release/source commit in map lock file. Actual local filesystem paths, binary models and private evidence remain local. Reserved IDs in example below are not an active manifest.
## Geographic instances (map only)
Keep existing source inventory schema. Local binding table keyed by stable building_id (from dataset+source_id), with source_ids for confirmed multipart grouping, source_snapshot_hash, model_id (nullable), manifest_sha256, match_status UNKNOWN/CANDIDATE/CONFLICT/CORROBORATED/APPROVED, evidence refs, chosen anchor projected E/N, pilot CRS, heading_grid_deg, vertical_mode and offset_m, scale (default 1), epoch, review. Multiple same model IDs may serve distinct buildings; one source can be part of a complex, never delete or double-place unresolved relations. Match by independently corroborated address, geometry, series, levels, facade, date and dimensions. No automatic nearest guess or random replacement; group similarity is not historical series. Reject missing/retired model, wrong version/hash, wrong dependencies, unapproved rights, unresolved pivot or facade. Missing bindings stay unresolved with reason; never fake a P3D or scale to fit.
## Spatial contract
GIS geometry WGS84 lon,lat; pilot EPSG:32636 only, SW E=294373.084 N=5698122.108 m, 1920m square, 64x64x30m. World-local x=E-E0, y=N-N0, metres. Production origin/CRS unapproved. Model canonical interchange local +X right,+Y forward,+Z up, facade_forward_xy explicit, ground contact anchor measured; not claim actual Blender/P3D/TB axes. Heading is degrees clockwise from grid north. Convert by measured adapter, not assume TB yaw equals azimuth; test 0/90/180/270 and asymmetric mesh. For default +Y forward, x'=x*cos(h)+y*sin(h), y'=-x*sin(h)+y*cos(h) after subtracting local anchor; add target anchor. For other facade vector use rotation difference. Z mode relative or absolute explicit, never mix ASL/ATL/datum; GM only for actual elevations. TB XShift=200000 only once in verified serializer, not canonical coordinate. No automatic slope tilt or non-unit scale; foundation handling separately reviewed. Half-open core sector ownership + halo; dedup by canonical instance ID, not rounded positions. No actual placement authorized now.
## GRM and Terrain Builder
Pinned upstream jetelain/ArmaRealMap v0.11.1 SHA 2aef2040836daa11a8a368bb0c7f9ecd8f405d65. Map owns custom .grma3a generation/adapter from approved manifest, inspect exact Buildings schema and dependencies in source. Do not invent JSON fields or copy upstream asset pack. GRM may select procedural generic models; explicit reviewed real building bindings must override/exclude generic building generation in future, not duplicate. No current GRM native building layer, no new elevations by GRM, no gentb/full generation. Map creates TML/template and import adapter from exact model paths and validates actual file/template name, offsets and format, not assuming CfgVehicles is TML name. Future map config requiredAddons[] uses actual required CfgPatches of placed assets, e.g. ZPB_Buildings_60 only after release. No circular dependencies. P3D materials/textures use same approved virtual prefixes. Future integrated test one asymmetric building, one known point, verify location/heading/ground contact in TB/Buldozer/engine and missing addon failure; separate approval needed.
