## 3. Предлагаемая схема будущего сопоставления

1. Не изменять source OSM snapshot и stable source_id. Каталожные ID, адреса, алиасы и фактические OSM contours хранить независимо.
2. Нормализовать язык улицы, пробелы, кириллицу/латиницу, дробные и буквенные номера, сохраняя оригинал. Адрес — не уникальный ключ: городской список содержит две записи Героев Сталинграда 1 разных серий; несколько объектов имеют один адрес 3А.
3. Проверить координаты/контур, этажность, число секций и характер фасада на фотографиях. Группы G-ID из PR #47 — предложения, не типовые проекты. Не назначать серию всем членам группы без независимой проверки.
4. Статусы: UNKNOWN (не проверялось), CANDIDATE (каталожный/адресный ориентир), CONFLICT (противоречие), CORROBORATED (географическое и визуальное подтверждение конкретного здания), MODEL_READY (измеренные размеры, достаточные виды/планы, права и эпоха одобрены). Для CORROBORATED нужно независимое географическое и визуальное основание; одна совпадающая строка не подходит.
5. Будущий контракт: source_id, catalog_id, raw_address, aliases, series_candidate, match_status, reference_urls, dimensions_with_units_and_source, section_count, levels, facade_orientation, uncertainty, epoch, license_status. Отсутствующее значение null; не подставлять типовую высоту вместо измерения.
6. Предложение для модели серии 60: отдельные торцевые и рядовые секции, цоколь, крыша, входы, лоджии, швы, поздние пристройки и разрушения. Сначала сверить геометрию 4/6/8 секций, затем выбрать общие детали; не масштабировать дом целиком ради вписывания в OSM. Исторический слой, визуальный прокси и игровой слой независимы.
