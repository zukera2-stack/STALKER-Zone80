# MAP-003 — исправление последовательности: GRID FIRST → SOURCE SECOND

**Решение владельца 24.11.2026:** предыдущие GIS-выходы `60×62` не готовились под квадратную игровую сетку. Исправляем **алгоритм подготовки**, а не считаем Global Mapper неисправным. Цель: **одна** реально покрытая источником `64×64×30м` сетка в `EPSG:32636` с **0 NoData**, затем отдельная проверка Global Mapper 26.2 Pro и, только при безопасной изоляции, одно terrain-only испытание в Terrain Builder. Не размещать дома, сооружения, дороги как Arma objects, не создавать игровые модели.

## Зафиксированная геометрия пилота (НЕ утверждение сетки всего мира)

| Параметр | Значение |
|---|---|
| Проекция | EPSG:32636, UTM 36N, метры |
| `ncols`, `nrows` | **64 × 64 = 4096** |
| `cellsize` | **30 м** |
| `xllcorner`, `yllcorner` | **294373.084 E / 5698122.108 N** |
| `east`, `north` край | **296293.084 E / 5700042.108 N** |
| Размер пробной территории | **1920 × 1920 м** |
| WGS84 bbox исходного кандидата | запад 30.045; юг 51.398; восток 30.070; север 51.414 |
| Прежний GIS-полуфабрикат | 60×62×30м, XLL 294433.084 / YLL 5698152.108 |
| Отступ старого охвата | новый квадрат: **+60м слева/справа, +30м сверху/снизу** |
| `NoData` | 0 обязательно для выбранной импортируемой сетки |

Реальная `64²` grid должна быть **зафиксирована до чтения источника**. Четыре угла прежнего WGS84 bbox проходят внутри этого квадрата при обратимом EPSG:4326↔32636 преобразовании (проверить в автоматическом тесте). Нельзя обрезать DSM по произвольному широтно-долготному bbox и только затем экпортировать в метры с автоматическим охватывающим прямоугольником: именно это дало 60×62 и 253 `NoData`.

## Получение правдивого рельефа

`tools/map003/build_fixed_grid.py` выбирает **сначала** GRID 64²×30м в UTM36 и обращается к исходному публичному **Copernicus GLO-30 COG** только для значений, необходимых этим 4096 целевым ячейкам. Устаревшую вырезку 60×58 WGS84 **не растягивать**; старые 60×62 и их 253 пробела не интерполировать. При билинейном пересчёте используются **реальные соседние исходные пиксели**; это метод репроекции, а не создание дополнительных измерений или «исправление» отсутствующих данных. Вход — DSM со зданиями/растительностью и вертикалью EGM2008 по паспортным данным, **не** фактическая съёмка чистой поверхности грунта.

Одноразовый [GitHub Actions workflow `.github/workflows/map003-fixed-grid.yml`](../../.github/workflows/map003-fixed-grid.yml) создаёт **краткоживущий артефакт**, а не коммит GIS файлов в публичный репозиторий. Только если каждый целевой пиксель имеет исходное высотное покрытие — файлы `pilot-tb-64x64.asc`, `pilot-tb-64x64.tif`, `GRID_MANIFEST.json` с 5 контрольными ячейками, SHA и границами. Если источник не покрывает квадрат, статус `BLOCKED`, без заливки `-9999`/0, без фальшивых высот и без TB импорта. Фактический результат конкретного workflow фиксировать **после запуска**.

## Роль Global Mapper 26.2 Pro

**Global Mapper 26.2 Pro 64-bit остаётся основным локальным картографическим инструментом.** После получения краткоживущего исходного артефакта локальная Луна сверяет SHA, открывает новый `EPSG:32636` GeoTIFF в **фактически установленной GM26.2 Pro**, проверяет 64×64/30м/NoData/полный geotransform/5 samples, затем штатным `.gms` получает локальный ASC из **того же готового квадратного GeoTIFF**. Если экспорт изменяет количество строк/ширину/позицию: STOP и целевое исправление скрипта (без переопределения географического grid). Сырые исходники в ignored `reports/MAP-003/<run-id>`; output hash, журнал, единицы измерения, GMS script version, CRS. Не считать GitHub Python rasterio эквивалентом реального запуска Global Mapper.

### Terrain Builder — отдельно, после карты высот

Только если файловые GIS проверки PASS и можно гарантировать, что пользовательский открытый TB проект **никоим образом не изменится**, разрешён **один** terrain-only импорт в новый пустой project-owned TB sandbox (только высоты; не здания). Если защита текущего проекта невозможна, TB `BLOCKED` и карта-высотный артефакт всё равно полезен; не запускать TB заново, не трогать P:, не моделировать здания, не Binarize/WRP/PBO, не перескакивать в Stage 002.
