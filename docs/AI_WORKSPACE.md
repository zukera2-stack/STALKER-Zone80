# AI_WORKSPACE — единый регламент ChatGPT / Cursor
Дата принятия: 28.11.2026. Решение владельца; отменяет прежний канал ChatGPT Library и Desktop Commander. Не изменяет технические допуски.

## Роли
ChatGPT — ведущий разработчик и аналитик: исследования, архитектура, алгоритмы, код, все доступные локальной среде вычисления/тесты, самостоятельный разбор результатов, исправления, готовые скрипты, укрупнённые задания и независимая приёмка. Cursor/Codex — локальный исполнитель: запускает предоставленные или необходимые локальные скрипты (PowerShell для Windows/Arma Tools), работает с программами владельца, выполняет нативные тесты, собирает доказательства, исполняет порученные исправления. Не перекладывать доступные ChatGPT тесты/анализ на Cursor. Не считать отчёт исполнителя независимой приёмкой.

## Каналы и дерево
GitHub — код, задания, Issue, документация, skills, контракты, статусы и краткие отчёты. Google Drive — разрешённые модели, текстуры, архивы, логи, screenshots, native exports и иные файлы. Library — исторический источник, не основной канал передачи. Desktop Commander и другие удалённые PC plugins не использовать. Не вводить публичный доступ, не менять sharing, не загружать секреты или запрещённые лицензией данные.

Корень: [AI_WORKSPACE](https://drive.google.com/drive/folders/1fMW1TznED-OZitjxaF_ndjKi4WuRWOiD).
Проекты: STALKER-Pripyat-Buildings, STALKER-Zone80, stalker_anomaly_monsters, KineForge, Stellar-Atlas. В каждом INPUT (ChatGPT → Cursor), OUTPUT (Cursor → ChatGPT), QA (доказательства), ARCHIVE (завершённые этапы). Текущий проект: [STALKER-Zone80](https://drive.google.com/drive/folders/1KquBp4BwGfOTWhUYlEndIUyN96BOviZa). Структура 5×4 проверена через Drive 28.11.2026; локальное монтирование ещё не проверено. Не создавать дубль AI_WORKSPACE при недоступности.

## Локальный исполнитель
Определить локальный Google Drive for desktop самостоятельно: список доступных PSDrive FileSystem/томов, проверка конфигурации и фактического каталога My Drive/Мой диск или зеркальной папки. Проверять только подходящие корни, не сканировать всё содержимое дисков. Не угадывать букву, не использовать P: для передачи, не монтировать диск и не менять ACL. Подтвердить точные четыре каталога именно своего проекта; при нескольких кандидатах не выбирать произвольный. PowerShell: Get-PSDrive -PSProvider FileSystem; Test-Path -LiteralPath; Get-Item -LiteralPath. Рабочие native проекты, lock/intent/checkpoint, временные файлы и логи создаются в разрешённой локальной sandbox; Drive — только завершённая передача, не live рабочая папка и не замена Git checkout. ChatGPT использует подключённый Google Drive, проверяет метаданные и скачивает доступные исходные байты в свою среду; не предполагает наличие доступа к диску ПК.

## Передача и проверка
1. Сформировать комплект в локальной sandbox. Уникальное имя: PROJECT_GATE_UTC_RUNID.zip (не переиспользовать имя). Внутри manifest.json или SHA256SUMS: относительный путь, размер и SHA256 каждого payload файла (исключить сам манифест из собственного списка); также gate, commit SHA, назначение, статус и границы доказательства. Архиву вычислить отдельный SHA256 и размер. Проверить ZIP и все записи, запрещать абсолютные/выходящие пути и дубликаты.
2. Передавать только необходимые и разрешённые файлы, без перезаписи; завершить сборку до копирования. Проверить размер и SHA256 после копирования в выбранную папку, дождаться подтверждения синхронизации облаком в доступном канале. Не считать локальное копирование доказательством cloud upload. Не публиковать raw files в GitHub.
3. Issue: логический путь AI_WORKSPACE/PROJECT/{INPUT|OUTPUT|QA|ARCHIVE}/filename, размер в байтах, SHA256 архива, назначение, run ID/commit, ссылка Drive если наблюдалась, состояние local copy/cloud sync. Получатель скачивает реальные байты, проверяет SHA256 и манифест до распаковки/использования. Не считать метаданные или чужое заявление проверкой байтов. Не перезаписывать утверждённые исходники и не удалять чужие результаты.
4. При недоступности Drive оставить комплект локально, указать точный blocker, локальное имя/путь в допустимом redacted виде, размер/hash и статус PENDING_TRANSFER; продолжать независимые доступные этапы. Не утверждать upload без подтверждения. Не мигрировать старые Library snapshots автоматически, сохранять их ссылки/хеши как исторические.
5. Только подтверждённые испытания — PASS. Остальное PARTIAL/BLOCKED/NOT RUN. Не повторять принятые тесты без причины. Архивирование не равно одобрению или stage promotion.
